# Replace with a product specification title

## Problem

Describe the evidenced user problem.

## Evidence

Link discovery notes or other evidence and distinguish facts from assumptions.

## Users

Identify affected users and situations.

## Desired Outcomes

Describe measurable changes for users or the product.

## Non-goals

State what this specification deliberately excludes.

## Scope

Define the smallest coherent capability being considered.

## Requirements

List behavior or constraints without prematurely choosing implementation.

## Acceptance Criteria

Describe observable evidence that the requirements and outcomes are satisfied.

## Affected Contexts

Link every context named in the `contexts` metadata field, or state `None.`

## Decisions

Link every decision named in the `decisions` metadata field, or state `None.`

## Risks

Describe meaningful product, domain, delivery, or adoption risks.

## Open Questions

Record unresolved questions. Accepted specifications must say `None.`
